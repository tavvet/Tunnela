# Tunnela build status

Baseline verification date: October 6, 2026. Documentation and language work: October 7, 2026. Published target: Windows x64, self-contained .NET 10.

## Start with Windows — 0.1.0-preview.5, October 26, 2026

- **Service.** Unchanged: after an EXE installation it already starts with Windows (Automatic, not delayed) and waits idle. The development `install-dev.ps1` still registers Manual startup.
- **GUI at sign-in.** New **Settings** option *Start Tunnela in the notification area when I sign in to Windows*. It writes or removes one per-user value, `Tunnela`, under `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, with the fixed command `"%ProgramFiles%\Tunnela\desktop\Tunnela.Desktop.exe" --tray`. It applies immediately, is available only in the installed copy, and shows when Windows Startup settings have turned the entry off. It never connects the VPN.
- **`--tray` start.** The window is created but not shown, and status polling starts at once. Starting Tunnela again from Start now opens the running copy's window through a per-session, per-user event instead of showing an "already running" message; it first passes its foreground right on with `AllowSetForegroundWindow`, so the window can come to the front. A second `--tray` start exits silently. If that event cannot be created, only this activation is lost.
- **Uninstall.** After a successful uninstall, the backend removes the entry for the account that approved UAC and, when signed in, for the recorded controller account. Only an entry whose command starts with this installation's quoted executable path is removed, so the GUI's arguments can change without breaking cleanup. The NSIS script is unchanged.
- **Updates.** With the option on, the GUI usually runs in the tray, so the installer refuses until **Close interface…** is chosen. Its message and the option's hint now say so; the installer still never closes the application itself.
- **Review of this branch.** Fixed: foreground activation, second-instance decisions extracted into `SingleInstance` and covered by tests, the checkbox re-read deferred until the binding update ends (`StartupSetting`), controller-account cleanup, and the single command rule shared by the GUI and the uninstaller.
- Release build: 0 warnings, 0 errors. 152 isolated tests passed, 0 skipped: 79 Core, 62 Desktop (32 new, using temporary registry keys under `HKCU\Software\Tunnela.Tests` that are deleted afterwards), 11 Service. 83 isolated installer assertions passed; their registry checks also use only such a temporary key. NSIS 3.13 compiled the installer with `/WX` and no warnings.
- Foreground activation, the deferred checkbox refresh in a real WPF window, and cleanup in another loaded user hive are not verified by automated tests.
- The build script now targets `0.1.0-preview.5` (Windows file version `0.1.0.5`) and produces `.artifacts\installer\Tunnela-0.1.0-preview.5-Setup-x64.exe`. No application, installer, sign-in start, Windows service, or VPN was launched. See [the manual checks](TESTING.md#starting-with-windows).

## Review fixes — 0.1.0-preview.4, October 26, 2026

- **Pipe accept loop.** A client that opened a pipe instance and closed it before the service accepted it made `WaitForConnectionAsync` throw `IOException` (ERROR_NO_DATA). The exception escaped `ControlPipeWorker`, which stops the .NET host; stopping the service requests a VPN disconnect. The loop now replaces only that pipe instance and keeps serving. A new isolated test reproduces the race on a private, randomly named local pipe, and a characterization test confirms the Windows behaviour.
- **Exit confirmation.** **Disconnect and exit** treated the service's `Error` state as an unconfirmed disconnect, so it warned even when no engine process existed (for example, after an unexpected engine exit or a failed start). An accepted disconnect with no process and state `Disconnected` or `Error` now closes without that warning; `Unknown` or any remaining process still asks for confirmation.
- **Service data folder.** The service used to take over an existing `%ProgramData%\Tunnela` folder by rewriting its owner and permissions. Standard users can create that folder before installation, and a handle opened before such a rewrite keeps its access. The service now creates each folder with its SYSTEM/Administrators-only descriptor in one step and refuses an existing folder that is redirected, owned by a non-administrator, or writable by non-administrators. Existing installations created by the service already meet this requirement. The installer reports an untrusted folder before any change and never removes or re-permissions it.
- **SDK bootstrap.** `bootstrap-sdk.ps1` rewrote Microsoft's download URL to the retired `dotnetcli.azureedge.net` mirror. It now downloads from the URL in the release metadata, uses basic parsing, and disables the slow PowerShell 5.1 progress display. Selection was checked offline against the cached metadata; a fresh SDK download was not performed.
- **Follow-up review of these fixes.** The first loop fix retried every accept `IOException` forever without a trace, and a failure to create the replacement pipe instance still stopped the service. Now only the Win32 results for a departed client (ERROR_NO_DATA, ERROR_BROKEN_PIPE, ERROR_PIPE_NOT_CONNECTED) are retried at once. Other accept failures and pipe-creation failures are retried with delays doubling from 200 ms to 5 s, recorded as a sanitized `Service.ControlChannelFault` diagnostic, and reset by the next accepted client. After 20 consecutive faults, about 75 seconds of continuous failure, the error escapes and the service stops visibly instead of appearing to run without a control channel. An accepted request is still served when its replacement instance cannot be created.
- **Fresh-install folder creation.** The creation path is now covered by isolated tests: the exact service descriptor (`O:BAD:P(A;OICI;FA;;;SY)(A;OICI;FA;;;BA)`), and creation under a parent that grants the test user inheritable full control, confirming that only the protected SYSTEM/Administrators ACL is applied by the create call. The tests use the current user as owner because a non-elevated test cannot assign Administrators. LocalSystem assigning the Administrators owner at creation, and a first installation on a machine without `%ProgramData%\Tunnela`, remain unverified; see [the focused checks](TESTING.md#after-the-review-fixes).
- Release build: 0 warnings, 0 errors. 120 isolated tests passed, 0 skipped: 79 Core, 30 Desktop, 11 Service (new `Tunnela.Service.Tests`). The pipe tests passed in eight consecutive runs. 76 isolated installer assertions passed in Windows PowerShell 5.1.
- No application, installer, Windows service, or VPN was launched. These fixes are not verified on the installed product; see [the focused checks](TESTING.md#after-the-review-fixes). The build script now targets `0.1.0-preview.4` (Windows file version `0.1.0.4`), but that installer has not been built or tested.
